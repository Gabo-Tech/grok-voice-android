Develop

How the app is put together.

These notes match the tree on main at 0.1.65. The short contributor path is CONTRIBUTING.md. Release signing steps also live in RELEASING.md. Screen rules are DESIGN-LANGUAGE.md.

Architecture

The UI is React and Vite. Tauri 2 hosts it. On Android the WebView sits in ai.grokvoice.app. Rust owns the microphone, the vault, the stores, and the model runtimes.

  • Session. xAI and OpenAI are realtime voice. Each xAI call mints a short-lived client secret with POST https://api.x.ai/v1/realtime/client_secrets, then connects to wss://api.x.ai/v1/realtime. The long-lived key is not sent on the socket. OpenAI uses its own key the same way. 1min.ai is a text model: Moonshine and the on-device voice stay on the phone. On-device Talk waits for a pause, then runs a GGUF. It is not full-duplex barge-in.
  • Audio. Uplink is 16 kHz PCM16. Downlink is 24 kHz PCM16. On Android the capture is an AudioRecord owned by the microphone foreground service. cpal is the desktop capture and the speaker.
  • Tools. actions::tool_definitions in src-tauri/src/actions.rs is the phone tool list, and it appends finance::tool_definitions. Cloud sessions and 1min.ai use that list. remember_fact and forget_fact are added only in the on-device session (local_memory.rs).
  • Vault. Keys live in a Stronghold snapshot. On Android the snapshot key is wrapped by a non-exportable Android Keystore key.
  • Wake word. rustpotter, trained from three recordings on the phone. The samples are not uploaded.
  • Stores. Notes, Time, the in-app calendar, People, Finance, settings, talk history, and web preferences are local files. The list is persist::STORES. Talk and the screen share them. There is no bank login and no cloud sync. Backup version 2 covers that list. A passphrase uses AES-256-GCM and PBKDF2. Without one, the file is plain and contains the API keys. Model weights are named, not copied. backupRoundTrip.test.ts fails if a new key is stored without being listed.

Tauri and Android build

You need Node, pnpm, Rust, a JDK, and the Android SDK with NDK 27.1.12297006. CI uses Rust 1.94.1, Temurin 17, Node 26.0.0, pnpm 10.33.0, platform android-37.0, and build-tools 37.0.0.

pnpm install
pnpm tauri dev

That is the desktop shell. Phone alarms, the calendar provider, the keystore, and the foreground service run on Android.

export ANDROID_HOME="$HOME/Android/Sdk"
export ANDROID_NDK_HOME="$HOME/Android/Sdk/ndk/27.1.12297006"
export NDK_HOME="$ANDROID_NDK_HOME"

pnpm tauri android dev
pnpm tauri android build --target aarch64 --apk

The release APK is written to:

src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk

pnpm tauri android init is only for a missing src-tauri/gen/android. This repository already contains that project. build.rs downloads sherpa-onnx v1.13.8 and llama.cpp tag b12774, and it builds libptts_ffi. Model weights are not in the APK.

arm64-v8a

minSdk is 26 and targetSdk is 37 in src-tauri/gen/android/app/build.gradle.kts. The release command targets aarch64. The workflow rejects an APK whose badging ABI or lib/ entries are anything other than arm64-v8a, and it requires lib/arm64-v8a/libptts_ffi.so.

Signing with the debug certificate

The release build type uses the debug signing config. The Gradle comment says “Local sideload key. Replace this with an upload keystore before Play Store.” A local APK is therefore signed with the debug keystore on that machine.

The Release APK workflow signs that file again with apksigner (v2 only) and the repository secrets:

  • ANDROID_KEYSTORE_BASE64
  • ANDROID_KEYSTORE_PASSWORD
  • ANDROID_KEY_ALIAS
  • ANDROID_KEY_PASSWORD

It accepts one certificate, SHA-256 fd400ffe61c9b18654bc40f567275e5a6e13bab8d311355f389f6e46458aafe9. That is the sideload certificate the README calls the debug key. An APK signed by another certificate does not install over an existing copy. GitHub cannot show the secrets again. Keep an offline backup of the keystore.

CI: Build and sign

The workflow file is .github/workflows/release-apk.yml. The workflow name is Release APK. The job name is Build and sign. It runs on ubuntu-24.04 with a 180 minute limit.

  • A pull request into main builds, signs, and verifies. It does not upload a release. The tag it checks is v plus the version in src-tauri/tauri.conf.json.
  • A push of a v* tag builds the same APK and uploads GrokVoice-X.Y.Z.apk to that GitHub release, creating the release when it is missing. A tag push does not replace an asset that is already there.
  • Manual dispatch takes a tag and a dry-run flag. Dry run skips the upload. Manual dispatch can replace the asset with --clobber.

Before the native build, the job runs:

node --experimental-strip-types --test src/lib/setupGuide.test.ts src/lib/i18nCoverage.test.ts

Verify checks versionName, versionCode, minSdk 26, the arm64-v8a ABI, v2 signing, the certificate, and libptts_ffi.so. The 0.1.65 release asset is 58,162,590 bytes, sha256 a1d569de0c02c9a81eedd6f15cd5931472dc8d5284754f3107216db534821313.

Versioning

versionName is the version string. versionCode is major * 1000000 + minor * 1000 + patch. For 0.1.65 that is 1065. The workflow computes it the same way and compares it to aapt dump badging. Gradle reads tauri.android.versionCode and tauri.android.versionName from the generated tauri.properties.

The 0.1.65 bump changed these files:

  • package.json
  • src-tauri/tauri.conf.json
  • src-tauri/Cargo.toml and src-tauri/Cargo.lock
  • src-tauri/src/local/phonon.rs (the Hugging Face user-agent GrokVoice/0.1.65)
  • README.md and docs/index.html, where the user-facing copy names the version

Merge the bump to main, tag that commit vX.Y.Z, and push the tag. See RELEASING.md.

Translations and the check

Locales are en, es, de, pt, and ca-ES-valencia. English is the key. t("…") and fill("…") in src/ must exist in every other catalog. Android strings.xml files are values, values-es, values-de, values-pt, and values-b+ca+ES+valencia. Apostrophes in those XML files are written as \'. Spoken lines are the EN, ES, DE, PT, and CA tables in src-tauri/src/i18n.rs.

The check is src/lib/i18nCoverage.test.ts plus src/lib/setupGuide.test.ts. CI runs both before the APK build. Run them locally with the same command as the workflow. A new English string that is missing, empty, or still identical in another locale fails the test, except for names the test keeps on purpose.

Tests

JavaScript tests are the src/lib/*.test.ts files, run with Node’s test runner (node --experimental-strip-types --test). The CI job runs the setup and i18n files. The others cover finance math, colors, appearance, budgets, and time tabs.

Rust unit tests live next to the modules under src-tauri/src. Run them with:

cargo test --manifest-path src-tauri/Cargo.toml

The Release APK workflow does not run that cargo suite. It compiles the Android release instead.

DESIGN-LANGUAGE.md

Read it before changing a screen, sheet, dialog, widget, or theme. Themes may set only the semantic tokens it lists, through data-appearance. No raw hex in a component. No pure black or white. Text is at least 13px. Targets are at least 44px. Radius stays on 0, 2, and 4px. One accent. Primary actions are solid fills. Secondary actions are underlined text. This site uses the Graphite tokens from src/index.css.

Contribute

Follow CONTRIBUTING.md. A new field or a new kind of record needs create, read, update, and delete on the screen and in Talk, in all five locales. Deletes that remove a saved record wait for a clear yes. Talk does not create an account, a card, or another record the person did not ask for.
